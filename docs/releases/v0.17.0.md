# v0.17.0 — Visual Smoke Tests

## Overview

Version v0.17.0 adds a browser-based visual smoke test. There are **no app
behavior changes** — this is read-only browsing plus assertions, closing a
real gap: `streamlit.testing.v1.AppTest` verifies widget structure and text,
but never renders CSS or a real layout, so it cannot catch a broken
active-button color, viewport overflow, or a warning that's technically
present but visually hidden.

## What it does

`scripts/visual_smoke.py` boots the app headless with Playwright + Chromium
and walks the landing page plus all seven workflows through the guided-route
navigation, asserting on every screen:

- No horizontal overflow at a 1280px desktop viewport.
- The active route/workflow button is readable (text color differs from its
  background; not fully transparent).
- No positive compliance claim appears without a negation — the same check
  as `tests/test_no_claims.py`, applied to rendered page text instead of
  AppTest markdown.
- At least one warning/info alert is visible per workflow.
- The app version and all three route cards render on the landing page.

It also drives one real interaction — selecting `gs1:gtin` and clicking
"Generate Candidates" — so the Generate Mapping Candidates screenshot shows
the v0.16.0 promotion-lane state rather than an empty form. Each screen is
captured as a full-page PNG.

## Installation and CI

- New optional dependency group: `pip install -e ".[visual]"` (adds
  `playwright` without touching the default `dev` install).
- New CI job `visual-smoke`, separate from the blocking `test` job, with
  `continue-on-error: true` while the harness stabilizes against real
  browser timing. Screenshots upload as a build artifact
  (`visual-smoke-screenshots`) on every run.
- Screenshots are git-ignored (`tests/visual/baselines/`): this version
  captures and asserts on live layout, not pixel-diff comparison against a
  committed baseline — that's a natural follow-up once the harness has
  proven stable over several runs. See `docs/visual-smoke.md` for the full
  rationale and how to extend it to new screens.

## Preserved

- No app behavior changes; converter, mapping registry, mapping catalog,
  and Web Vocabulary snapshots are untouched.
- No warnings suppressed; no mock data; no fabricated coverage/compliance.
- The default `pytest` run is unaffected — Playwright is only required for
  the separate `visual` extra and CI job.
