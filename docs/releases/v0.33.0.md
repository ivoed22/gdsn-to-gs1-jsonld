# v0.33.0 — UI Overhaul Within Streamlit

## Overview

Fourth version of the end-product build path. v0.30.0 consolidated the
structure; this version brings the interaction layer up to the same
standard, staying entirely within Streamlit + the existing DESIGN.md
token system. Design guidance came from the ui-ux-pro-max skill (dark
palettes as desaturated tonal variants rather than inversions, contrast
verified per theme, progressive disclosure, one primary action per
screen, tabular data presentation); DESIGN.md and the no-claims rules
took precedence wherever they overlapped.

## What changed

### Progressive disclosure (Mapping Governance)

The candidates page previously stacked ~10 controls before any content.
The five filter controls (confidence levels, review statuses, the two
include-checkboxes, limit per property) now live in a collapsed
"Filters" expander; the page leads with the WebVoc property selector,
the review-lane choice, the sign-off uploader, and one primary
"Generate Candidates" action. All filter defaults are unchanged —
never expanding the panel gives exactly the pre-v0.33.0 behavior.

### Grid-style SDR annotation editing (Standards Review)

The v0.29.0 "Record a review annotation" section rendered six stacked
four-column forms. It is now one `st.data_editor` grid: SDR id and
title read-only, Reviewer / Decision date / Proposed status / Notes
editable per row, with the proposed status constrained to the fixed
vocabulary through a SelectboxColumn. The grid feeds the exact same
`build_sdr_review_annotation` helper and download; no schema change.

Deliberately deferred: the hard-mapping sign-off form in Mapping
Governance keeps its per-candidate widget layout. Its AppTest
(`test_hard_mapping_signoff_authoring_produces_downloadable_json`)
drives real selectbox/text-input interactions, and `st.data_editor`
has no AppTest accessor — converting it would have traded interaction
test coverage for visual consistency. The SDR grid's AppTest was
rewritten to assert clean rendering instead; its authoring logic is
covered by the pure unit tests in `tests/test_standards_backlog.py`.

### Table presentation

- Explore's property table: pinned Property column, compact Coverage
  and SDR-indicator columns.
- Candidate results table: pinned WebVoc-property column, scores
  formatted `%.3f`, promotion eligibility rendered as checkboxes.

### Dark mode (custom CSS layer)

`app/ui.py` gains a `prefers-color-scheme: dark` block at the end of
the stylesheet: the `:root` tokens switch to desaturated, lightened
tonal variants (surfaces `#0f1722`/`#16202e`, text `#e6edf7`/`#9fb0c7`,
borders `#2c3c50`, accent `#6db3e8`), plus targeted overrides for the
hardcoded light surfaces (sidebar panels, status cards/badges, warning
boxes, workflow-card marks). Placement at the end of the stylesheet
matters: the first attempt sat before the component rules and lost
every equal-specificity conflict — caught by a dark-emulated browser
screenshot, then verified fixed the same way. Streamlit's own widgets
follow the user's Streamlit theme setting; this covers the custom
component layer.

### Deprecation sweep

All 48 `use_container_width=True` occurrences across `app/` replaced
with `width="stretch"` (the upstream replacement; the old parameter's
removal deadline had passed). Test runs are free of the per-element
deprecation warnings.

## Verification

- Full suite green (315 tests), including the rewritten SDR-grid
  AppTest and all existing candidates/standards interaction tests
  (filter widgets remain reachable inside the collapsed expander).
- Visual smoke passing locally; light-theme baselines regenerated.
- Dark theme verified via a Chromium `color_scheme="dark"` screenshot
  (sidebar panels, governance boxes, workflow cards, metrics all
  readable; borders visible).

## Preserved

- No behavior changes: converter, serializer, validators, downloads,
  and the report are untouched.
- No warnings suppressed; no-claims text unchanged (test-enforced).
