# v0.25.0 — In-UI Hard-Mapping Review Sign-Off Authoring

## Overview

Since v0.16.0, promoting a hard-mapping-lane candidate to `accepted`
requires a dedicated human sign-off recorded in a JSON file
(`mapping_promotion.load_reviewed_hard_mappings`). Until now, producing
that file meant hand-editing JSON outside the app. This version adds an
in-UI authoring form so a reviewer never has to hand-edit that file.

## What changed

- New `mapping_promotion.build_hard_mapping_signoff(reviews:
  list[dict]) -> dict`. Each input entry looks like `{"candidate_id",
  "reviewer", "date", "decision", "notes"}` with `decision` one of
  `"approved"`/`"rejected"`. Only `"approved"` entries are included in
  the output's `reviewed_candidate_ids` list — the *only* key
  `load_reviewed_hard_mappings` reads — so a file built this way is
  byte-compatible with a hand-edited one. The output also carries a
  `reviews` array with the full per-candidate audit trail (reviewer,
  date, decision, notes), which the loader simply ignores.
- `app/workflows/candidates.py`'s Generate Mapping Candidates workflow
  gains a new "Author hard-mapping review sign-off" section, shown
  whenever the current result set includes hard-mapping-lane candidates:
  - One row per hard-mapping candidate: Reviewer (text), Date (date
    picker), Decision (Not reviewed / Approved / Rejected), Notes (text).
  - Once any candidate has a non-"Not reviewed" decision, a caption shows
    the approved/rejected counts and a "Download hard-mapping review
    sign-off JSON" button appears.

## What did NOT change

- `mapping_promotion.py`'s promotion logic (`compute_promotion_eligibility`,
  `annotate_promotion_fields`, `build_promotion_artifact`) is untouched.
- The sign-off file's schema is unchanged and still hand-editable exactly
  as before; this only adds a second way to produce it.
- The UI never auto-applies an authored sign-off to the current session's
  eligibility. The reviewer downloads the file and uploads it back
  through the existing "Hard-mapping review sign-off (optional JSON)"
  uploader, then regenerates candidates — the same two-step flow as
  before, just without needing an external text editor.
- Nothing here writes to mapping YAML, the mapping registry, or the
  mapping catalog.

## Preserved

- No warnings suppressed; no mock data; no fabricated coverage/compliance.
- No official GS1 validation or production compliance claimed.
