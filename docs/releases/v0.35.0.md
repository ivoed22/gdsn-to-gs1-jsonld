# v0.35.0 — Workspace Persistence (Light)

## Overview

Sixth and final version of the approved end-product build path
(v0.30.0–v0.35.0). Reviewer work — hard-mapping sign-offs, SDR review
annotations, loaded candidate reports — previously evaporated with the
Streamlit session. It now survives in a git-ignored local `workspace/`
directory as plain JSON. Deliberately light: no database, no history,
one current file per artifact kind.

## What changed

- **New pure module `src/gdsn_to_gs1_jsonld/workspace.py`:**
  `save_artifact(kind, payload)`, `load_artifact(kind)`,
  `list_artifacts()` over a fixed artifact-kind vocabulary
  (`hard_mapping_signoff`, `sdr_review_annotations`,
  `candidate_report`). One `workspace/{kind}.json` per kind; saving
  overwrites; absent or corrupt files load as `None` (a broken
  convenience file never takes a workflow down). No timestamps inside
  payloads — file mtime is filesystem metadata, not artifact content.
- **Governance constraint is structural, not procedural:** the fixed
  kind vocabulary plus fixed per-kind filenames make it impossible for
  this module to write anywhere but the workspace directory. Governed
  data (`mapping/`, `mapping_catalog/`, `docs/standards-decisions/`)
  cannot be touched from here — and an unknown kind raises before any
  filesystem access.
- **Mapping Governance:** the hard-mapping sign-off authoring section
  gains "Save sign-off to workspace" next to the download; the sign-off
  uploader offers "Use hard-mapping sign-off saved in workspace/" when
  the artifact exists (an uploaded file always takes precedence); the
  results section gains "Save report to workspace" and the load-report
  area a "Load report from workspace" button feeding the exact same
  parse/annotate path as an uploaded report.
- **Standards Review:** the SDR annotation section gains "Save
  annotations to workspace" and a collapsed read-only view of
  previously saved annotations. The editing grid always starts fresh:
  a review proposal is re-authored deliberately, never silently
  replayed into the editor.
- `workspace/` added to `.gitignore`. Every save surfaces the written
  path; every load states its workspace origin.

## Verification

- 6 unit tests (`tests/test_workspace.py`): round-trip for every kind,
  overwrite semantics, absent/corrupt → None, unknown kind rejected
  before any write, unserializable payload rejected, inventory listing.
  All against tmp_path — the real `workspace/` is never touched.
- 1 new AppTest: drives sign-off authoring, clicks "Save sign-off to
  workspace" against a monkeypatched (call-time-resolved) directory,
  verifies the written JSON and that the workspace option then appears.
- Full suite: 327 passed.
