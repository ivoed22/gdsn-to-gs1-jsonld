# v0.22.0 — Bulk ZIP Codelist Validation

## Overview

v0.21.0 wired codelist validation into the Single XML workflow but left
the Bulk ZIP workflow without any codelist visibility. This version closes
that gap: the same v0.20.0 codelist registry now validates every file in a
batch, and the Bulk ZIP workflow shows an aggregate result. No converter
behavior change, no new download — this is a read-only diagnostic panel,
same as v0.21.0.

## What changed

- `batch_converter.convert_batch_zip` gains a fully opt-in
  `codelist_registry: dict | None = None` parameter, threaded through to
  each file's `convert_xml_to_jsonld` call. Leaving it `None` (the
  default) is byte-identical to every prior version.
- `BatchFileResult` gains a `codelist_status_counts: dict[str, int]` field
  (per-file status counts).
- The batch summary gains an aggregate `codelist_validation_counts` dict,
  exposed as `BatchConversionReport.codelist_validation_counts`.
- `app/workflows/convert.py`'s Bulk ZIP workflow now loads the cached
  codelist registry (the same loader v0.21.0 added) and shows a new
  "Open codelist validation (Track D)" expander after conversion:
  - Five metrics (Valid / Unknown / Deprecated / Missing / Source
    Unavailable), summed across every file in the batch.
  - A table of files that had at least one non-valid codelist entry, with
    per-status counts — so a reviewer can see which files need attention
    without opening every file's own report.
- The `codelist issues` count (non-valid entries) is also added as a
  column in the existing per-file preview table for at-a-glance triage.

## What did NOT change

- Batch success/failure counts, the export ZIP contents, and per-file
  `jsonld_data`/`mapping_report_rows`/`validation_report`/
  `unmapped_fields` are unaffected — confirmed by test.
- Codelist validation never excludes a file from the batch or changes its
  status; a file with unknown/deprecated codelist values still converts
  successfully and appears in the export ZIP exactly as before.

## Example fixture result

Batching the committed example product shows the same result as the
Single XML workflow: **5 valid, 2 unknown** (the already-documented
`DPP_DOCUMENT`/`CERTIFICATION_DOCUMENT` sentinel values).

## Preserved

- Converter and batch-converter output unchanged for callers that don't
  pass `codelist_registry` (test-proven).
- No warnings suppressed; no mock data; no fabricated coverage/compliance.
- No official GS1 validation or production compliance claimed.

## No official validation

This release does not claim official GS1 validation.
This release does not claim production readiness.
A `valid` codelist status means the value matches the imported registry —
it is not an official GS1 conformance determination.
