# v0.24.0 — Offline Vocabulary Freshness Check

## Overview

`gdsn-to-gs1-jsonld check-webvoc-updates` has existed as a CLI-only
command since v0.6.0, and by default it fetches GS1's live vocabulary
URLs (`--no-network` opts out). That's an acceptable, explicit, human-
invoked CLI operation, but it must never be wired into the Streamlit app
as-is — this project's hard rule is that it does not fetch online
resources. This version surfaces the useful *capability* (seeing what
changed in an updated vocabulary before adopting it) in the UI, built on
a new function that is offline by construction, not by flag.

## What changed

- New `webvoc_monitor.compare_webvoc_snapshot_bytes(snapshot_dir,
  comparison_jsonld_bytes) -> dict`: diffs the pinned local
  `gs1Voc.jsonld` against a second JSON-LD file already in memory (e.g.
  Streamlit's uploaded-file bytes). Reuses the existing `_jsonld_terms`/
  `_jsonld_metadata`/`_changed_records`/`sha256_bytes` helpers. Contains
  **no** `urlopen` call in its code path — there is nothing to disable,
  it simply cannot reach the network.
- `app/workflows/standards.py`'s Standards Review workflow gains a new
  "Vocabulary freshness check" section (Step 2, below the existing SDR
  summary): a file uploader for a candidate `gs1Voc.jsonld`, and once
  uploaded, four metrics (local terms, uploaded terms, new terms, changed
  terms), a version/modified caption, and — when a difference exists — a
  warning plus an expander with new/removed/changed term tables.
- If nothing is uploaded, the panel shows a caption pointing to
  `docs/webvoc-update-monitor.md` for the CLI's network-capable check,
  making clear that's a separate, explicitly human-invoked path.

## What did NOT change

- The CLI `check-webvoc-updates` command and its underlying
  `check_webvoc_updates()` function are untouched — same optional network
  fetch, same `--no-network`/`--update-snapshot` flags.
- Nothing in the UI writes to `webvoc/current/` or any governed data.
  Deciding whether to actually adopt an uploaded candidate snapshot
  remains a separate, explicit, out-of-band review step.
- Standards Review's existing SDR summary (Step 1) is unchanged.

## Preserved

- No warnings suppressed; no mock data; no fabricated coverage/compliance.
- No online fetching anywhere in the app — confirmed by construction
  (the new function has no network code path to disable) and by test.
- No official GS1 validation or production compliance claimed.
