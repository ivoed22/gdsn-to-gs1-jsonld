# v0.19.0 — Builder Manifest Expansion Analysis (Track C)

## Overview

Version v0.19.0 adds read-only analysis of which WebVoc properties are
mature enough to add to the Manual JSON-LD Prototype Builder manifest next.
The builder manifest, mapping registry, mapping catalog, and Web Vocabulary
snapshots are all unchanged — this is a proposal for a human to approve, not
an automatic expansion.

## What it does

The Builder manifest currently authors 183 of the 553 GS1 Web Vocabulary
properties. New `src/gdsn_to_gs1_jsonld/builder_expansion_analysis.py`
classifies each of the other 371 into a fixed readiness vocabulary:

- **`ready_now`** — has governed mapping evidence (from the consolidated
  mapping registry's catalog, v0.15.0); not hard-mapping; not
  controlled-vocabulary shaped.
- **`needs_codelist_curation`** — has evidence, but looks
  controlled-vocabulary shaped, so manifest `options` would need curating
  first (the same work existing `code`-type fields already require).
- **`needs_hard_mapping_review`** — has evidence, but that evidence's GDSN
  attribute is a Track B hard mapping (v0.16.0's exact
  `detect_hard_mapping` rules, reused as-is against whichever GDSN
  attribute is cited as evidence) and needs the same dedicated review as
  any other hard mapping.
- **`not_ready_no_evidence`** — no governed mapping evidence at all.

On the current committed data: 5 `ready_now`, 0 `needs_codelist_curation`, 0
`needs_hard_mapping_review`, 366 `not_ready_no_evidence`. That small
ready-now count is an honest reflection of how small the governed mapping
registry still is (28 accepted GDSN attributes) — this analysis does not
manufacture readiness beyond what's actually governed.

## DPP relevance is never assessed

Every candidate reports `dpp_relevance: "not_yet_assessed_pending_crosswalk"`.
Judging DPP relevance is the GS1-first DPP Crosswalk's job — now sequenced
as **v0.20.0+** (moved back one slot to make room for this track) — and this
version does not fabricate that judgment in its absence.

## New workflow and CLI

- **"Builder Manifest Expansion Analysis"** (marker EXP), added under the
  **Vocabulary & Mapping** route alongside Explore, Generate Mapping
  Candidates, and Standards Review. Shows a coverage summary, a
  readiness-phase filter, a candidate table, per-candidate detail, and a
  JSON download. There is no "add to manifest" action anywhere in it.
- **CLI**: `gdsn-to-gs1-jsonld analyze-builder-expansion` writes
  `builder_manifest_expansion_analysis.json`.

See `docs/builder-manifest-expansion-analysis.md` for the full input list,
phase definitions, and CLI usage.

## Preserved

- Builder manifest, mapping registry, mapping catalog, and Web Vocabulary
  snapshots are unchanged.
- No warnings suppressed; no mock data; no fabricated coverage/compliance.
- No codelist enforcement is claimed; `codelist_dependency` is an authoring-
  effort heuristic, not a validation result.

## No official validation

This release does not claim official GS1 validation.
This release does not claim production readiness.
This release does not assess or claim DPP relevance for any property.
