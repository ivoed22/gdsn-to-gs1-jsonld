# v0.18.0 — Builder UX at Scale

## Overview

With the Manual JSON-LD Prototype Builder's manifest at 183 fields across 19
groups, this version adds the navigation and status aids needed to work at
that scale, and fixes a real defect found while building them. The
builder's state model, serializer (`serialize_builder_state_to_jsonld`), and
validator (`validate_builder_state`) are unchanged.

## Coverage overview

A table across every group in the selected product category — field count,
filled, missing (required), flagged for review — computed from the same
persisted values the live JSON-LD preview already uses. Switching groups no
longer means losing sight of the rest of the form.

## Per-field status chips

New `src/gdsn_to_gs1_jsonld/builder_status.py` (pure functions, no Streamlit
dependency, unit-tested) derives one status per field:

`filled` · `missing` · `review_required` · `hard_mapping_review` ·
`codelist_pending` · `external_source_required` · `extension_candidate` ·
`blocked`

Two of these — `external_source_required` and `extension_candidate` — are
**reserved and never triggered today**. They would flag a field needing a
promoted hard mapping's reference lookup, or a Crosswalk-identified
extension candidate — neither exists yet (hard mappings are scored, not
auto-promoted, per v0.16.0; the Crosswalk is v0.19.0+). The vocabulary
includes them so downstream UI has a stable status set to render against
once that data exists, not because fabricating a value for them today would
be honest.

**Hard-mapping review reuses Track B's detection exactly.** The same
deterministic `detect_hard_mapping` rules that flag hard mappings in the
Mapping Candidate Generator (cross-references to `Country`,
`PartyIdentification`, `PartyInRole`, `EntityIdentification`,
`TradeItemIdentification`, `CatalogueItemReference`, plus GLN/cross-item-GTIN
name patterns) are applied to whatever GDSN evidence is already linked to a
builder field's WebVoc property, via a cheap bms_id lookup against the
committed GDSN reference data — no new candidate scoring required.

## Search, filter, evidence, export

- A text search (label / property id / help text) and a status multiselect
  narrow the fields shown in the current group.
- Fields with catalog evidence get an expander showing the GDSN attribute
  name, BMS ID, XPath, mapping status, and confidence.
- The download/clear controls now sit under an explicit "Export" section
  with the current group's fill/missing/flagged counts alongside the
  download button.

## Bug fix: controlled-vocabulary fields now show real options

Before this version, every `code`-type field's dropdown silently showed only
the "— none —" placeholder. The manifest's per-field `options` list was
parsed into the property-metadata index used to build catalog evidence, but
never copied into the merged metadata dict the render layer reads —
`options` was dropped at that merge step. Fields with real controlled
vocabularies, e.g. `gs1:packagingMarkedLabelAccreditation` (30+ real values),
were effectively unusable as controlled-vocabulary inputs. Fixed by carrying
`options` through `_property_metadata_index`, confirmed with a regression
test.

## Preserved

- Builder serializer, validator, and state model are unchanged.
- Converter logic, mapping registry, mapping catalog, and Web Vocabulary
  snapshots are untouched.
- No warnings suppressed; no mock data; no fabricated coverage/compliance.
- No status is fabricated for the two reserved vocabulary values.
