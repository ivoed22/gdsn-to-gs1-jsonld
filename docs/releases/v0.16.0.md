# v0.16.0 — Full-Scope Mapping Scoring & Review Lanes

## Overview

Version v0.16.0 (Track B) extends the Mapping Candidate Generator so every
scored GDSN/WebVoc pair routes through a review lane on the way to the same
terminal status, and can be run at full scope against the entire GDSN
attribute reference. Review-only, exactly like every prior version of this
tool: nothing here writes mapping YAML, the mapping registry, or the mapping
catalog. Converter behavior, batch behavior, and single-file output are
unchanged.

## Hard-mapping detection

Every candidate now carries:

| Field | Meaning |
|---|---|
| `hard_mapping` | `true` if the GDSN attribute is a cross-reference or identifier reaching outside the current product XML message |
| `hard_mapping_reasons` | Human-readable reasons |
| `review_lane` | `"standard"` or `"hard_mapping"` |

Detection is deterministic, from the reference-data `class_associated_to` /
`named_association` columns (cross-class references into `Country`,
`PartyIdentification`, `PartyInRole`, `EntityIdentification`,
`TradeItemIdentification`, `CatalogueItemReference`) plus GLN and
cross-item-GTIN attribute-name patterns — never a semantic guess. The
product's own `gtin` is explicitly excluded (it identifies the item itself,
not a reference to another entity). Embedded value objects fully contained
in the message (`Address`, `DateOptionalTime`, and similar) are not flagged:
nesting alone does not make a mapping hard.

On the committed reference data (BMS 3.1.36, 7,171 rows / 6,067 leaf
attributes), 478 attributes (~6.7%) are flagged hard-mapping.

## Promotion lanes — same destination, different review gate

**Both lanes reach the same terminal status.** `hard_mapping` is a flag with
an extra review gate, never a separate or permanent status:

- **Standard lane**: score → review → `accepted`.
- **Hard-mapping lane**: score → dedicated extra review → `accepted`.

New `src/gdsn_to_gs1_jsonld/mapping_promotion.py` computes:

- `status` — the fixed registry status vocabulary (`proposed` /
  `review_required` / `accepted` / `rejected` / `deprecated` / `blocked`;
  see [`mapping-consolidation.md`](mapping-consolidation.md)). There is no
  `hard_mapping_candidate` status.
- `promotion_eligible` — standard-lane candidates are eligible once their
  own `review_status` carries no blocker. Hard-mapping-lane candidates are
  **never** eligible from scoring alone: they additionally require their
  `candidate_id` to appear in a human-curated hard-mapping review sign-off
  file. Passing that gate makes them eligible for exactly the same
  `accepted` status as a standard-lane candidate.

Every `generate-mapping-candidates` run writes a reviewable `promotion/`
report (summary + per-lane JSON/CSV + eligible-for-promotion). Reaching
`promotion_eligible: true` still writes nothing — promoting a candidate into
the governed mapping registry remains a separate, deliberate standards
decision.

## Full-scope scoring

`--full-scope` scores all 553 WebVoc properties against the complete
~6,067-row GDSN attribute reference in one run. Measured at **~7 minutes**
on the committed reference data — documented as a local/offline operation,
deliberately **not** part of the CI-blocking smoke test, which stays scoped
to a single property (`--property gs1:gtin`) for speed. `--full-scope`
cannot be combined with `--property`.

## UI

The Generate Mapping Candidates workflow gained:

- A review-lane filter (all / standard / hard_mapping).
- An optional hard-mapping review sign-off JSON upload.
- Promotion-lane metrics (standard lane, hard-mapping lane, eligible for
  promotion, hard-mapping reviews recorded).
- Lane / status / promotion-eligibility columns in the candidate table.
- Status, lane, and promotion-eligibility badges plus hard-mapping reasons
  in the candidate detail panel, using the status-badge tokens introduced in
  v0.15.0.

The candidate generator's cached inputs now read the consolidated mapping
registry (`mapping/mapping_registry.yaml`) rather than the archived
`mapping_v0_3.yaml`, matching the rest of the app since v0.15.0.

## Preserved

- Converter logic, batch behavior, and single-file output are unchanged.
- Mapping YAML, the mapping registry, the mapping catalog, and Web
  Vocabulary snapshots are unchanged — this tool only reads them.
- No warnings suppressed; no mock data; no fabricated coverage/compliance.
- No hard mapping is promoted automatically; no permanent block exists.

## No official validation

This release does not claim official GS1 validation.
This release does not claim production readiness.
`promotion_eligible: true` is a review-support signal, not an official GS1
decision or an applied mapping.
