# v0.21.0 — Codelist Validation UI (Track D UI Wiring)

## Overview

v0.20.0 built the codelist import and validation machinery but explicitly
left Streamlit wiring for a later version. This version adds it: the
Convert GDSN XML workflow now shows codelist validation results. No
converter behavior change, no new download — this is a read-only
diagnostic panel.

## What changed

- `app/workflows/convert.py` gains a cached codelist-registry loader
  (`_load_codelist_registry_cached`) and passes it into
  `convert_xml_to_jsonld(codelist_registry=...)`.
- Inside the existing **Step 2 — Review mapping & evidence**, a new
  expander "Open codelist validation (Track D)" shows:
  - Five metrics (Valid / Unknown / Deprecated / Missing / Source
    Unavailable) with counts.
  - A table of every codelist-backed field checked.
  - A per-entry detail view with a status badge (reusing the v0.15.0
    status-badge tokens: valid=accepted/green, unknown/deprecated=review/
    amber, missing/source_unavailable=archived/grey) and the full
    validation detail text.
- If the codelist registry can't be loaded for any reason, the panel says
  so and conversion proceeds exactly as before — the opt-in design from
  v0.20.0 is unchanged.

## What did NOT change

- The four existing downloads (JSON-LD, mapping report XLSX, validation
  report JSON, unmapped fields JSON) are unaffected — confirmed by test.
- `jsonld_data`, `mapping_report_rows`, `validation_report`, and
  `unmapped_fields` are identical to pre-v0.21.0 output.
- The guided four-step structure (Upload → Mapping → Validate → Export) is
  unchanged; the new panel lives inside the existing Step 2, not a new
  step.

## Example fixture result

Converting the committed example product shows **5 valid, 2 unknown**. The
two unknowns (`DPP_DOCUMENT`, `CERTIFICATION_DOCUMENT` for
`referenced_file_type`) are the already-documented experimental sentinel
values from `docs/v0.3.0-design.md` — not real GS1 `ReferencedFileTypeCode`
values, and not a bug.

## Preserved

- Converter output unchanged (test-proven).
- No warnings suppressed; no mock data; no fabricated coverage/compliance.
- No official GS1 validation or production compliance claimed.

## No official validation

This release does not claim official GS1 validation.
This release does not claim production readiness.
A `valid` codelist status means the value matches the imported registry —
it is not an official GS1 conformance determination.
