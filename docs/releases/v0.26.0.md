# v0.26.0 — Cross-Workflow Deep Links

## Overview

The last of five "quick win" versions (v0.22.0–v0.26.0). Reviewing a
WebVoc property referenced in Generate Mapping Candidates previously
meant manually switching to Explore and re-typing the property to find
it. This version adds a one-click deep link.

## What changed

- New `app/workflow_shared.py` function:
  `navigate_to_webvoc_property(property_id: str) -> None`. Follows the
  same `st.button(on_click=..., args=(...))` callback pattern already
  used by `set_workflow_mode`/`set_route`. It sets:
  - `selected_route = "vocabulary_mapping"` and
    `workflow_mode = "Explore GS1 Web Vocabulary"`.
  - Explore's Group/Domain/Coverage filters back to "All ..." and both
    checkboxes to `False`, so a stale filter can't hide the target
    property.
  - Explore's search box to *property_id* (a near-guaranteed unique
    match on the exact term).
  - Explore's detail selectbox to *property_id*.
- `app/workflows/candidates.py`'s candidate detail expander gains a
  "View in Explorer" button directly under the WebVoc property code
  block, wired to the new callback with the candidate's
  `webvoc_property_id`.
- `app/workflows/explore.py`'s six filter/search/checkbox widgets and the
  detail selectbox gained explicit `key=` parameters (previously
  auto-keyed by Streamlit, which can't be targeted from outside).

## A regression this version had to guard against

Giving the detail selectbox an explicit key makes its value persist in
`st.session_state` across reruns — necessary for the deep link, but it
also means a *stale* selection could survive a search/filter change and
no longer be a valid option, which `st.selectbox` treats as an error.
Fixed with a small guard: before rendering the selectbox, if the stored
value isn't in the current filtered list, it's reset to the first match
— exactly matching Explore's pre-v0.26.0 behavior (which always
defaulted fresh to the first filtered result on every change) for anyone
not using the deep link.

## What did NOT change

- Explore's own data loading, filtering logic, and rendered content are
  untouched — only widget keys were added.
- No new computation or data source. The deep link is pure session-state
  wiring around already-existing render logic.
- Only one source workflow (Generate Mapping Candidates) got the "View in
  Explorer" button in this version; extending it elsewhere (e.g. Convert
  GDSN XML's mapping trace) is a natural, separately-scoped follow-up.

## Preserved

- No warnings suppressed; no mock data; no fabricated coverage/compliance.
- No official GS1 validation or production compliance claimed.
