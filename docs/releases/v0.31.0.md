# v0.31.0 — DPP Readiness Scorecard

## Overview

Second version of the end-product build path (see `docs/roadmap.md`).
After v0.30.0 gave the product five clear destinations, this version
gives it a hero artifact: one deterministic readiness panel per converted
product, summarizing *traceability & structural readiness* — explicitly
never a compliance verdict.

## What changed

- **New pure module `src/gdsn_to_gs1_jsonld/readiness.py`.**
  `assess_readiness(validation_report=..., mapping_report_rows=...,
  unmapped_fields=..., codelist_validation=...)` reads only fields an
  existing `ConversionResult` already carries. Dimensions:
  - *structural_validation* — `passed` / `passed_with_warnings` /
    `errors`, with error/warning counts.
  - *mapping_coverage* — `full_profile_coverage` /
    `partial_profile_coverage`, with mapped/total profile rows and the
    count of populated source elements outside the profile.
  - *codelist_conformance* — `all_valid` / `issues_found` /
    `not_evaluated` (when the conversion ran without a codelist
    registry — never a fake clean result), with per-status counts.
  - *dpp_relevance* — always `not_yet_assessed_pending_crosswalk`:
    judging which fields matter for a Digital Product Passport is the
    GS1-first DPP Crosswalk's job (v0.36.0+, not built). Same honesty
    pattern as `builder_expansion_analysis`.
- **Overall readiness level, fixed transparent rules, no invented
  score.** `review_required` on structural errors; `attention_points`
  on warnings, partial coverage, or codelist issues;
  `structurally_ready` only when every evaluated dimension is clean.
  There is deliberately no single numeric score anywhere in the
  payload: any weighting between dimensions would be fabricated.
- **Convert (Single XML) step 3 renders the scorecard** after a
  conversion: a level badge (text label, never color-only), four
  dimension metrics with the full detail as tooltips, and the scope
  note: "Traceability & structural readiness signals only — not
  official GS1 validation, no production compliance claim, and no EU
  DPP conformity assessment." Exactly 4 downloads remain (test-enforced).
- **Visual smoke hardening** (follow-up to the v0.30.0 non-blocking CI
  failure): the Mapping Governance candidate-generation drive retries
  once with a fresh open-type-click attempt when the BaseWeb dropdown
  misses the first typed filter on slow runners.

## Verification

- 8 new unit tests (`tests/test_readiness.py`) covering every level
  derivation, the not-evaluated codelist path, the always-not-assessed
  DPP dimension, the absence of a numeric score, the no-claims-safe
  scope note, and a real-fixture cross-check (5 valid / 2 unknown
  codelist entries → `issues_found` → `attention_points`, with coverage
  counts matching the conversion exactly).
- 1 new AppTest (`test_readiness_scorecard_appears_after_conversion`).
- Full suite: 309 passed. No-claims suites unchanged and green.

## Preserved

- No converter/serializer/validator changes; the scorecard is pure
  presentation over already-computed signals.
- No warnings suppressed; no official GS1 validation or production
  compliance claimed.
