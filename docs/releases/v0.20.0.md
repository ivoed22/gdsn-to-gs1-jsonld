# v0.20.0 — Codelist Import & Enforcement (Track D)

## Overview

Track D was blocked since it was first scoped (v0.16.0/v0.19.0): the
committed GDSN reference data had 507 codelist *names* but zero value
enumerations, and this project does not fetch data online or fabricate
values. This session the user provided the official public **GDSN and
Shared Common Code Lists** workbook for release 3.1.36, unblocking the
work.

## Source

`reference_data/raw_public/GDSN_and_Shared_Code_Lists_r3p1p36_i6_8May2026.xlsx`
— 595 codelists, 14,564 values, 509 deprecated values (with sunset
release). Inventoried in `reference_data/source_manifest.json`
(`gdsn_and_shared_code_lists_r3p1p36_i6`) with a SHA-256 checksum and the
same license/rights note already used for the GDSN BMS/XPath workbook:
"Public GS1 standards reference material. Use for traceability and review;
do not imply redistributed ownership beyond the project inventory copy."
The file was provided directly by the user; since the exact public GS1
download URL was not independently confirmed, `source_url` is a
project-internal URN rather than a guessed link.

## Import

New `src/gdsn_to_gs1_jsonld/codelist_importer.py` and CLI command
`import-codelists` parse the workbook's `CodeList` and `Deleted Codes`
sheets into a deterministic, versioned registry —
`reference_data/normalized/gdsn_codelists_r3_1_36.json` (committed):
codelist name, semantic resource URN, domain, status, allowed values
(value/label/definition/status), and deprecated values (with sunset
release).

## Validation

New `src/gdsn_to_gs1_jsonld/codelist_registry.py`:

- `validate_code_value(registry, codelist_name, value)` classifies a value
  as `valid` / `unknown` / `deprecated` / `missing` / `source_unavailable`
  (case-insensitive, trimmed).
- `CODELIST_DEPENDENCIES` maps six `CanonicalProduct` fields to their real
  codelist names — a **curated, independently verified table**, not derived
  from the mapping registry catalog's `code_list` column. That governed
  column predates several YAML field renames (e.g. it says
  `nutrients[].preparation_state`, the real field is
  `preparation_state_code`) and contains at least one clearly incorrect
  entry (`product_image_url` mapped to a codelist, which makes no semantic
  sense for a URL field). Every entry in `CODELIST_DEPENDENCIES` was
  checked against both the real `CanonicalProduct` field name and the
  imported registry's actual codelist name before being included.

## Converter integration — fully opt-in

`convert_xml_to_jsonld` gains one new optional parameter:
`codelist_registry=None`.

- **Default (not passed)**: byte-identical to every version before
  v0.20.0. Verified by test: `jsonld_data`, `mapping_report_rows`,
  `validation_report`, and `unmapped_fields` are unaffected either way;
  `codelist_validation` is an empty list when not passed.
- **Passed a loaded registry**: `ConversionResult.codelist_validation`
  gains one entry per codelist-backed field. Nothing else changes.
  Conversion never fails because of a codelist mismatch — warning vs.
  blocking is entirely a decision for whatever calls the converter, built
  on top of this new diagnostic data.

On the committed example fixture, two `referenced_file_type` values come
back `unknown`: `DPP_DOCUMENT` and `CERTIFICATION_DOCUMENT` are
project-defined sentinel values for the already-documented experimental
`referencedDocument` mapping (`docs/v0.3.0-design.md`), not real GS1
`ReferencedFileTypeCode` values. This is a genuine, expected finding that
demonstrates the feature works — not a bug to fix.

## Not done in this version

- No Streamlit UI wiring for codelist validation results yet — a natural
  next step, not built here.
- No enforcement for codelist-backed fields outside the six verified
  `CODELIST_DEPENDENCIES` entries.
- No change to `mapping_catalog/*`'s `code_list` column data quality
  issues — that's governed data outside this project's edit authority.

## Preserved

- Converter `jsonld_data` output is unchanged in every case.
- Mapping registry, mapping catalog, and Web Vocabulary snapshots are
  unchanged.
- No warnings suppressed; no mock data; no fabricated coverage/compliance.
- No online fetching; the workbook was provided directly by the user.

## No official validation

This release does not claim official GS1 validation.
This release does not claim production readiness.
A `valid` codelist status means the value matches this imported registry —
it is not an official GS1 conformance determination.
