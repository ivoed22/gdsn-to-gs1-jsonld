# v0.35.1 — Upload-specific mapping suggestions

## Outcome

When an uploaded GDSN XML contains populated elements that are not emitted by
the active mapping, the converter now shows matching GS1 Web Vocabulary
candidates from the committed 60%+ analysis catalog.

## Safety model

- 90%+ is displayed as a **strong candidate — review required**.
- 60–<90% is displayed as a **possible match — review required**.
- No suggestion is automatically emitted into JSON-LD, including 100% name
  matches.
- Values remain present in the lossless unmapped evidence download.
- The JSON report includes the score, reasons, alternatives, source versions
  and an explicit `auto_emitted: false` marker.

The score measures heuristic similarity, not semantic approval. Definition,
domain, range, cardinality, nesting, units and codelists still require review.

## Why this is not a new mapping profile

A mapping profile is executable and determines the JSON-LD output. The
candidate catalog is advisory evidence. Keeping them separate prevents an
unreviewed similarity match from becoming product data while allowing online
users to discover likely mappings. Once candidates are reviewed and accepted,
they should be promoted together into a new versioned mapping file;
`mapping/mapping_v0_4.yaml` remains stable.

## Verification

- Catalog validation rejects any row that enables automatic emission.
- Unit tests cover thresholds, upload-specific matching and no-emission.
- Streamlit AppTest verifies that a real partial product upload displays the
  suggestion panel without changing generated JSON-LD.
- Batch conversion carries the same suggestions inside each unmapped report.
