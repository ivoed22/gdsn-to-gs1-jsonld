# v0.30.0 — Consolidation: Nine Workflows Become Five

## Overview

First version of the approved end-product build path. The strategic
decisions behind it (recorded 2026-07-07): the end product serves three
layers on one core — a showcase layer for stakeholders, an expert
workbench for standards/mapping reviewers, and an operational layer for
data teams; the UI ambition stays within Streamlit; and the nine-workflow
toolbox consolidates aggressively into a product with a spine.

This version is the structural half: fewer, clearer destinations and a
lighter landing page. It deliberately changes **no behavior** — the
converter, serializer, validators, and all governed data are untouched,
and every capability remains reachable.

## What changed

### Nine workflows → five

| Before (9) | After (5) |
|---|---|
| Convert GDSN XML | **Convert GDSN XML** (unchanged: Single XML / Bulk ZIP tabs) |
| Explore GS1 Web Vocabulary | **Explore GS1 Web Vocabulary** (unchanged) |
| Create JSON-LD Prototype + Builder Manifest Expansion Analysis | **Create JSON-LD Prototype** (Expansion Analysis is a tab — it is analysis *about* the builder manifest) |
| Generate Mapping Candidates + Standards Review | **Mapping Governance** (one review lifecycle: candidates, SDR annotations, vocabulary freshness) |
| Validate Product Passport Sources + Build Product Passport Prototype | **Product Passport** (tabs: Sources & validation / Build prototype passport) |

### Navigation and landing page

- The two-stage route→child card navigation (v0.13.3) is replaced by one
  "Choose a workflow" row with five direct cards. The routes existed to
  manage nine destinations; with five they only cost clicks and screen
  height.
- Landing page reduced from five stacked sections to three: hero →
  workbench status (v0.27.0 dashboard) → navigation. The traceability
  strip and "workflow entry" intro were removed.
- Sidebar tightened: brand, workspace status, sources, and exactly one
  governance block (previously two near-duplicates).

### Mapping profile selection

Moved from the global sidebar into Convert — the only workflow that uses
a mapping profile — behind a low-key "Mapping profile" expander
(`render_mapping_profile_selector` in `app/workflows/convert.py`). Same
widget key, same archived-profile warning, same clear-results-on-switch
behavior.

### Removed

- The Builder's "Product is for sale" checkbox — a self-described form
  helper that emitted no JSON-LD.
- `ROUTES`, `set_route`, and the route-card/traceability-strip/entry-intro
  component helpers (now-dead code in `app/workflow_shared.py` and
  `app/ui.py`).

## Verification

- Full test suite green (300 tests), including rewritten navigation
  AppTests and the no-claims suite against the new structure.
- Visual smoke (Playwright) rewritten for direct navigation: six screens
  (landing + five workflows), all assertions passing locally; baselines
  regenerated. The per-screen alert check now retries briefly to absorb
  Explore's first-render dataset build.
- Byte-compile and all seven CLI smokes unchanged and passing.

## Preserved

- No converter/serializer/validator changes; no governed file touched.
- No warnings suppressed; every workflow keeps its scope warnings and the
  sidebar keeps the governance negations (test-enforced).
- No official GS1 validation or production compliance claimed.
