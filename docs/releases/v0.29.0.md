# v0.29.0 — First Slice of the Standards Review Workflow

## Overview

Last of eight versions in this batch (v0.22.0–v0.29.0: five "quick wins"
plus three "bigger scope" versions). `docs/roadmap.md`'s "Standards-
review workflow (future)" section describes a full eventual scope:
assign named reviewers and decision dates, move records through
Proposed/Accepted/Rejected/Deferred, create versioned mapping changes
only for accepted decisions, retain compatibility tests and migration
notes. This version deliberately does **not** build that state machine —
only the smallest useful slice: recording a reviewer and decision date
against an open SDR.

## What was checked first

Before designing anything, the actual backlog schema
(`docs/standards-decisions/standards_review_backlog.json`) was read.
Each SDR record already has `id`, `title`, `status`, `category`,
`affected_fields`, `affected_properties`, `warning_count`,
`blocks_release`, `standards_review_required`, `recommended_owner` (a
role/group description, not a named individual), `target_release`,
`decision_file`, `issue_number`, `issue_url`. `standards_backlog.py`
already declares `VALID_DECISION_STATUSES = {"open", "proposed",
"accepted", "rejected", "deferred"}` — the exact target-state vocabulary
the future workflow will need — so this version reuses it rather than
inventing anything new.

## What changed

- New `gdsn_to_gs1_jsonld.standards_backlog.build_sdr_review_annotation
  (annotations: list[dict]) -> dict`: a pure function building a review-
  annotation artifact from `{sdr_id, reviewer, decision_date,
  proposed_status, notes}` entries. Entries with a blank `sdr_id` are
  dropped. `proposed_status` values come from `VALID_DECISION_STATUSES`
  minus `"open"` (the current default, not a proposable target).
- `app/workflows/standards.py` gains a new "Record a review annotation"
  section (Section 3, below the existing SDR summary and vocabulary
  freshness check):
  - One row per open SDR: Reviewer (text), Decision date (date picker),
    Proposed status (Not reviewed / proposed / accepted / rejected /
    deferred), Notes (text).
  - Once any SDR has a non-"Not reviewed" proposed status, a caption
    shows the annotation count and a "Download review annotations JSON"
    button appears.
- `docs/roadmap.md`'s Crosswalk section heading renumbered from
  `v0.22.0+` to `v0.30.0+` (also fixed two other stale `v0.22.0+`/
  `v0.20.0+` cross-references in `README.md` and
  `docs/builder-manifest-expansion-analysis.md` that predated this
  session's renumbering).

## What did NOT change (explicitly out of scope for this slice)

- No status transition is ever applied. An SDR annotated "accepted" here
  still shows `status: "open"` everywhere else in the app — recording a
  proposal is not the same as applying a decision.
- `docs/standards-decisions/standards_review_backlog.json` is never
  written to by this feature. That file is governed data; a human still
  updates it (and the corresponding `decision_file`) through the existing
  SDR/decision-file process.
- No versioned mapping changes, no compatibility-test/migration-note
  generation — those remain the full workflow's job, not this slice's.
- The existing SDR summary (Section 1) and vocabulary freshness check
  (Section 2) are unchanged.

## Preserved

- No warnings suppressed; no mock data; no fabricated coverage/compliance.
- No official GS1 validation or production compliance claimed.
